## Шаги

1. **Методички.** Удалить 5 старых PDF, положить 4 новых PDF (конвертация
   LibreOffice из docx, имена `Drupal_1.pdf` … `Drupal_4.pdf` — по номеру в комплекте).
2. **ЛР10 (стенд 8108/8109).** Пользователь и роль, контактная форма, карта сайта,
   микроразметка, антиспам, резервное копирование, статистика посещаемости,
   кэширование.
3. **ЛР11 (стенд 8110/8111).** Модуль с таблицей в БД, модуль слогана и смены
   конфигурации, модуль `news` (ссылка в admin/config, страница, блок с
   ограничениями), вычисляемое поле, View статей с фильтром по дате.
4. **Проверка.** `setup-labN.sh` с curl-гейтами, аудит фактического состояния
   через drush, скриншоты через CDP.
5. **Документация и коммит.** README лаб, корневой README и BACKLOG, коммит.

## Технические решения

- Каждая лаба — самодостаточный стенд: свой `Dockerfile`, `docker-compose.yml`
  (PostgreSQL + Drupal 11 + Adminer), свой `scripts/labN-config.php`.
- База сайта «Город24» разворачивается копией `lab8-config.php` (портал, каталог,
  новости), затем конфиг текущей лабы — как сделано в `lab9`.
- Drupal 11: модуль `statistics` ядром удалён, ставится contrib-бэкпорт
  `drupal/statistics` 1.0.1. Микроразметка — `schema_metatag` 3.1.0.
- Порты: ЛР10 — 8108 (сайт), 8109 (Adminer); ЛР11 — 8110, 8111.

## Риски

- `backup_migrate` 5.1.5 и `computed_field` 4.0.0 на Drupal 11 проверены только
  composer-резолвом; фактическую работу подтверждаем прогоном.
- Схема Schema.org настраивается через Metatag; если конфиг не даст JSON-LD —
  добавляем собственный модуль-вставку JSON-LD.
- Скриншоты делаются после полного прогона конфига, иначе кадры не соответствуют
  состоянию стенда.
