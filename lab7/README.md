# ЛР7 — Joomla: управление пользователями и уровни доступа

Дисциплина «Системы управления контентом». Задание — `labs/Joomla/Joomla-3.pdf`
(внутренняя нумерация документа «ЛР №6»). Сайт «Город24» перенесён из ЛР6.

## Стенд

- Проект Compose: `cms-joomla-lab7`
- Контейнеры: `db7` (MariaDB 11), `web7` (Joomla 5.4.9), `phpmyadmin7`
- Порты: сайт `8102`, phpMyAdmin `8103`
- Образ `web7` собирается из `Dockerfile` (база `joomla:5` + лимиты PHP)

## Адреса

| Что | Адрес | Логин |
|---|---|---|
| Сайт | http://localhost:8102 | — |
| Админка | http://localhost:8102/administrator | `admin` / `Gorod24!Admin2026` |
| phpMyAdmin | http://localhost:8103 | `joomla` / `joomla` |

Учётные записи стенда (пароль `Gorod24!User2026` для всех, кроме admin):

- `dekan` — группа «Деканат»
- `starosta1`, `starosta2`, `starosta3` — группа «Старосты»
- `student1`, `student2`, `student3` — группа «Студенты»

## Запуск

```sh
cd lab7
docker compose up -d --wait
sh setup-lab7.sh
```

Скрипт `setup-lab7.sh` идемпотентен: повторный запуск не ломает готовый сайт,
перекопирует скрипты из `scripts/` и перепроверит стенд.

## Что реализовано

### Пользователи и группы

Скрипт `scripts/lab7-users.php` создаёт группы (под `Registered`):
`Деканат`, `Старосты`, `Студенты` и пользователей `dekan`,
`starosta1..3`, `student1..3`. После создания пересчитываются вложенные
множества (`lft/rgt`) таблицы `jos_usergroups`, чтобы Joomla корректно
наследовала права.

### Уровни доступа (View Access Levels)

`scripts/lab7-levels.php` создаёт 5 уровней:
- `Для студентов` — студенты + старосты + декан
- `Для старост` — старосты + декан
- `Для старосты группы №1` — старосты + декан
- `Для старост групп №2 и №3` — старосты + декан
- `Для студентов группы №3` — студенты + старосты + декан

### Категории и материалы

`scripts/lab7-categories.php` создаёт 3 категории `com_content` с разными
уровнями доступа и правилами `core.create` в `jos_assets`:

1. `Деканат — группе №1` (уровень «Для старосты группы №1») — публикует только декан.
2. `Деканат — группам №2 и №3` (уровень «Для старост групп №2 и №3») — публикует только декан.
3. `Деканат и староста №3 — студентам №3` (уровень «Для студентов группы №3») — публикуют декан и староста №3.

Статьи создаются с `access`, равным уровню доступа категории, поэтому
материалы недоступны пользователям без соответствующего уровня.

### Права групп

`scripts/lab7-permissions.php` настраивает:
- декан: `core.login.site/admin`, `core.manage/create/edit/edit.state/delete`,
  `com_content.*`, `com_menus.*`, `com_users.*`, `com_config.manage`;
- староста: `core.login.site`, `core.create/edit/edit.own/edit.state`,
  `com_content.create/edit/edit.own/edit.state`;
- студент: только просмотр (`create/edit = 0`).

Права проставляются как в корневом активе, так и в активах компонентов
(`com_content`, `com_menus`, `com_users`, `com_config`), иначе актив
компонента переопределяет корневые правила.

### Пункты меню

`scripts/lab7-menu.php` создаёт:
- `Регистрация` (доступ Public)
- `Вход`
- `Создать материал (декан)` (доступ «Для старост»)
- `Создать материал (староста)` (доступ «Для старост»)

Ссылки ведут на `index.php?option=com_content&view=form&layout=edit`.

## Проверка

`setup-lab7.sh` проверяет:
- сайт отвечает и содержит «Город24»;
- админка доступна;
- страницы «Регистрация» и «Вход»;
- пункты меню создания материала возвращают 303/200 (доступ ограничен).

Ручная проверка ACL:
- гость: 403 на все закрытые материалы;
- `student3`: видит только материалы группы №3;
- `dekan`: видит все материалы и может создавать новые;
- `starosta3`: открывается форма создания материала.

## Ограничение реализации

Старосты объединены в одну группу «Старосты» (по упрощению методички).
Различие по номерам групп обеспечивается уровнями доступа и категориями,
а не отдельными группами CMS. Если нужна строгая привязка к конкретным
старостам/студентам, потребуется создать подгруппы «Староста №1..3» и
«Студенты группы №3» и переназначить пользователей.
