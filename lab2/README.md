# ЛР2: Знакомство с WordPress (Docker) — сайт «Город24»

> Стек Docker живёт в этой папке (`lab2/`): `docker-compose.yml`, `setup-gorod24.sh`, тема `theme/gorod24`, автонаполнение `scripts/setup-content.php`, отчёт в `report/`.

Новостной портал Минска на базе вёрстки из ЛР1 (вёрстка ЛР1 (`../lab1/site`)).
Тема сайта: `theme/gorod24`, автонаполнение: `scripts/setup-content.php`.

## Как запустить
```bash
docker compose up -d                 # поднять стек
sh setup-gorod24.sh                  # (первый раз) WP + плагины + тема gorod24 + контент
```

## Доступ
- Сайт: http://localhost:8080
- Админка: http://localhost:8080/wp-admin — `admin` / `admin123`
- phpMyAdmin (база): http://localhost:8082 — `wp` / `wppass`

## Что внутри
| Контейнер | Роль | Аналог в OpenServer |
|---|---|---|
| `db` (MariaDB 11) | база данных WordPress | MySQL из OpenServer |
| `web` | веб-сервер + PHP + движок WP | Apache + PHP из OpenServer |
| `wpcli` | WP-CLI — командная строка WP (автоматизация) | — |
| `phpmyadmin` | веб-интерфейс к базе | phpMyAdmin из OpenServer |

Проект compose называется `cms-wordpress-group` (`name:` в `docker-compose.yml`), но имена
контейнеров короткие — у каждого сервиса свой `container_name`, поэтому в `docker ps` видно
`db`, `web`, `wpcli`, `phpmyadmin` без префикса и суффикса `-1`. Тома: `cms-wordpress-db-data`,
`cms-wordpress-wp-data`.

**Почему MariaDB:** MySQL-совместимая БД без лицензионных ограничений Oracle; WordPress работает с ней без изменений. **Зачем OpenServer в ТЗ:** методичка под Windows — OpenServer это «Apache+MySQL+PHP в одном установщике»; Docker заменяет его тем же набором контейнеров.

## Персистентность данных
Данные WordPress (файлы) и БД лежат в томах `cms-wordpress-wp-data` и `cms-wordpress-db-data`:
- `docker compose restart` / `down` — **всё сохраняется**;
- только `docker compose down -v` удаляет тома (полный сброс).

## Полезные команды
```bash
docker compose up -d --wait                          # запустить
docker compose down                                  # остановить (данные остаются)
docker compose run --rm wpcli wp <команда>           # WP-CLI
docker compose cp <файл> wordpress:/var/www/html/…   # положить файл в WP
```

## ЛР3: WP Elementor. Создание шаблона

Автонаполнение: `scripts/setup-lab3.php` (запуск: `docker compose run --rm -T wpcli eval-file - < scripts/setup-lab3.php`).
Скрипт идемпотентен — повторный запуск пересоздаёт свои страницы, а не плодит дубли.

### Что сделано

1. **Лендинг Elementor** — страница `/` («Лендинг Город24»), **8 секций**:
   1. hero: заголовок, текст, кнопка (фон #f4f7fb);
   2. заголовок «Разделы портала»;
   3. **три колонки** icon-box: Политика / Экономика / Спорт;
   4. **две колонки**: карточка главной новости «Немига-2» (image-box) + текст с кнопкой (фон #e8eff6);
   5. культура и события;
   6. **три колонки** счётчиков: 120 новостей в неделю, 48 проверенных источников, 7 лет с редакцией;
   7. цитата редакции (бесплатный виджет toggle, фон #e8eff6);
   8. **две колонки**: текст «Предложить новость» + форма Contact Form 7.
   Установлена главной страницей сайта. Тема — **gorod24** (та же, что в ЛР1/ЛР2).
2. **Шаблон Elementor** — «Шаблон страницы Город24» сохранён в библиотеке
   (Элементор → Templates → My Templates, тип Page). Из него собрана страница `/reklama/`.
3. **Встроенный ИИ** — демонстрируется вручную в редакторе Elementor (иконки «✨» у полей
   текста и цветов): требует входа в аккаунт Elementor AI, автоматизировать нельзя.
4. **Встроенные блоки** — страница `/bloki/`: по одному блоку из каждой группы редактора —
   **Текст** (абзац, заголовок, список, цитата), **Медиа** (обложка, галерея, файл),
   **Дизайн** (кнопки, разделитель, колонки, таблица), **Виджеты** (поиск, свежие записи, рубрики),
   **Тема** (название и слоган сайта), **Встраивания** (YouTube), **Шаблоны** (синхронизированный
   блок «Блок портала Город24»).
5. **Плагины блоков** (2 шт., активны): **Kadence Blocks** (59 блоков), **Stackable — Gutenberg
   Blocks** (47 блоков).

### Что было исправлено при проверке

- **Колонки схлопывались.** Хелпер `g24_multi_col()` принимал ассоциативный массив с ключами
  `33 => …` трижды; PHP оставлял один элемент, поэтому вместо трёх колонок получалась одна
  (в БД лежали 7 секций вместо 8, а счётчики и рубрики были не в трёх колонках). Заменён на
  список пар `[размер, виджеты]`.
- **Счётчик показывал 0.** Использовалось поле `number`, которого у виджета нет. Elementor 4.3.2
  ждёт `starting_number` / `ending_number` / `title`.
- **Виджет `blockquote` — PRO.** Без лицензии Elementor подменяет его пустой промо-заглушкой,
  цитата не отображалась. Заменена на бесплатный `toggle`.
- **`toggle` показывал «Toggle #1».** Поля `tab_title` / `tab_content` лежат внутри повторителя
  `tabs`, а не на верхнем уровне виджета.
- **`image-box` показывал Lorem ipsum.** Поля называются `title_text` / `description_text`.
- **Версия Elementor в данных** была зашита как `3.0.0`; ставится `ELEMENTOR_VERSION` (4.3.2).
- **Скрипт не был идемпотентным** — каждый прогон создавал новые страницы; теперь перед
  созданием удаляет свои прошлые записи по слагу и заголовку.
- **Задание 4 покрывало не все группы** — добавлены «Тема» и «Шаблоны» (синхронизированный блок).
